# Topology validation implementation and acceptance

This revision implements the attached plan's repeatable automated gates and repairs confirmed findings. The acceptance command is `npm run test:acceptance`: it requires a clean, unchanged commit, runs three consecutive sanity evaluations without retries, then a complete release evaluation. Its result is written to `test-results/acceptance-final.json` and the self-contained `test-results/acceptance-final.md`. Those final-commit receipts are authoritative; earlier diagnostic runs, including failures, remain preserved.

The harness provisions owned disposable PostgreSQL and MinIO services and separates onboarding, seeded workflows, migration/restore, visual, Lighthouse, container and performance data. Every seeded browser test and integration file gets a pristine DB clone; browser tests get a separate production server. Missing required services, skipped tests and retry-only passes fail. Logs, traces, screenshots and machine reports are scrubbed for credentials, including base64 textual attachments. Developer data is never reset.

The feature inventory preserves 226 release contracts and inventories 202 page/API methods, nine packages and README promises. `feature-families.md` and `inventory.json` describe meaningful assertion scopes and explicit manual prerequisites. A passing suite is not a claim that every legacy manual substep is automated. Cases whose complete contract exceeds the current assertions retain a not-run manual status. Controlled provider failures, real CLI/MCP HTTP transport, full author/matrix/execute/triage/retest/report and quality-graph/snapshot/comparison workflows strengthen the previous heading-only evidence.

Repairs include audited persisted-generation share revocation, genuine XLSX workbooks and complete paginated PDF output, batched ingestion and historical statistics, Next server retry, theme/login hydration races, production reconciliation packaging, response security headers, the current Next proxy convention, bounded webhook retries, write-only webhook secrets, CLI bearer-only routing and a strict unauthenticated API sweep. See `findings.md` for reproductions and regressions. Production dependency audit reports zero advisories; seven development-only advisories remain in Vitest/tinypool/mocker and drizzle-kit/esbuild. They require a separately reviewed breaking development-tool update.

Eighteen light/dark visual references were inspected in the pinned Linux Playwright renderer. They cover primary screens, long-title wrapping, an editor, empty results and the actual server error. Release evaluation compares references without updating them. The actual Node22 production image, upgrade/reconciliation/idempotency, backup/restore and DB/object restart persistence are exercised. Scale gates record hardware, raw samples and fixture sizes: 50k cases HTTP/query p95 below 500 ms, usable 5k-result executor and 10k-result ingestion below 30 seconds. Lighthouse audits authenticated hub/cases/run pages.

Remaining qualifications require an authorized provider/OAuth/AI sandbox and scoped credentials; human VoiceOver/NVDA/native zoom operators; physical devices/native Safari; a disposable HTTPS/TLS/proxy/production Compose deployment and a separate disaster-recovery host; external package-consumer projects; and Office/Numbers/Sheets compatibility checks. Non-Latin PDF font compatibility needs manual assessment. Exact prerequisites and steps are retained per case in the inventory. Optional live reads are explicit and never counted as deterministic passes. Local measurements qualify the recorded environment, not arbitrary deployment hardware or sustained concurrency.

WebKit's upstream same-origin request cancellation issue during document replacement is retained in diagnostics and classified only for the exact WebKit/same-origin/error-suffix/pending-main-navigation condition ([upstream #43120](https://github.com/microsoft/playwright/issues/43120)). Other page errors fail. Linux WebKit does not certify native Safari. Webhook delivery is best-effort in-process with bounded retries and a stable delivery ID, not a durable queue; receivers must deduplicate deliveries. Empty-secret unsigned compatibility remains explicitly optional in the UI.

Optional product improvement: a denser long-title catalog mode may reduce row height; inspected wrapping remains readable and editable. Human discoverability and ergonomics remain unqualified.

No deployment, publication, push or merge is included. Apply migration `0006_report_share_generation` before running the updated app against an existing database.
